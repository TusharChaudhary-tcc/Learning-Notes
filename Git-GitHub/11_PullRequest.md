# 11_PullRequest

## What is a Pull Request (PR)?

A Pull Request (PR) is a request to merge your changes into another repository or branch.

It is mainly used in **open-source projects** and **team collaboration**.

---

## Why use Pull Requests?

- Review code before merging.
- Discuss changes with team members.
- Find and fix issues.
- Maintain code quality.

---

## Pull Request Workflow

```text
Original Repository
        │
        ▼
      Fork
        │
        ▼
 Clone to Local Computer
        │
        ▼
   Make Changes
        │
        ▼
 Commit & Push
        │
        ▼
 Create Pull Request
        │
        ▼
 Code Review
        │
        ▼
 Merge (if approved)
```

---

## Steps to Create a Pull Request

1. Fork the repository.
2. Clone your fork.
3. Create a new branch (recommended).
4. Make changes.
5. Commit your changes.
6. Push the branch to GitHub.
7. Click **New Pull Request**.
8. Add a title and description.
9. Submit the Pull Request.

---

## Benefits

- Easy collaboration.
- Code review before merging.
- Track discussions and changes.
- Improves code quality.

---

## Pull Request vs Push

| Push | Pull Request |
|------|--------------|
| Uploads code to your repository. | Requests to merge changes into another repository or branch. |
| No approval required (if you have permission). | Usually requires review and approval. |

---

## Important Points

- PR = Pull Request.
- Used for collaboration.
- Does **not** merge code automatically.
- Repository owner or team reviews the changes.
- If approved, the PR is merged.

---

## Summary

- **Push** → Upload your code.
- **Pull** → Download latest changes.
- **Pull Request** → Request to merge your changes.
